# Прямое взаимодействие и иерархический Assembly

[← Документация](README.md) · [Контракты данных](CONTENT_SCHEMA.md) · [Результаты приёмки](ASSEMBLY_V2_VERIFICATION.md)

**`part-of` описывает предмет; `Exhibit.assembly` описывает способ его исследования.**
Учебные группы не добавляют исторических сущностей. `trigger` и `trigger.guard`
остаются детьми пистолета, а трубки и крепления сопровождают ложу только в схеме.
Первый настроенный экспонат — пистолет 1798/1804; procedural и существующий GLB
используют одни контракты и индекс.

## Данные и выбор

`src/content/assembly.ts` определяет `Selection` (entity / layout-group / null),
`AssemblyContext` (assembled / именованный layout), `DisplayMode` и конфигурацию.
`ExhibitViewer` хранит один `SemanticState`; дерево, карточка и runtime получают
его через общую команду. `selectedEntityId` отдельно не хранится. Hover остаётся
в runtime. Обычный выбор не вызывает фокусирование камеры.

`SemanticPicker` пересекает все видимые meshes. Первое пересечение с policy
`solid` либо имеет владельца, либо блокирует выбор. Чистый `resolveSelection`
преобразует владельца в разрешённую сущность/группу текущей схемы. Opacity сама
по себе не меняет picking. `SemanticPresentation` явно разрешает `pick-through`
только для ghost-окружения, недоступного текущему layout. Выбираемые ghost-детали
продолжают блокировать луч.

Максимальное отклонение за весь жест ограничено 6 CSS px для мыши и 10 для touch.
Возврат в исходную точку не превращает drag в click; второй указатель и cancel
отменяют выбор. OrbitControls продолжает обрабатывать вращение и pinch.
Hover вычисляется максимум один раз за кадр и использует кешированные материалы;
выбор имеет приоритет. Материалы освобождаются при смене модели/dispose.

Семантические экспонаты не создают кружки и не запускают их покадровую проекцию.
Старые Hotspot и их проверки сохраняются для остальных экспонатов.

## Структура и материалы

ARIA-дерево содержит исключительно SemanticEntity/part-of. Есть вложенные groups,
roving tabindex, стрелки, Home/End, Enter/Space и Escape. Фокус клавиатуры отделён
от выбора; внешний выбор раскрывает предков без переноса фокуса. Виртуальные
группы доступны в интерфейсе схемы и подписаны «Группа схемы»; участники отмечены
в историческом дереве без фиктивного родителя. Карточки region/feature не имеют
изоляции или разборки. Навигация по пути содержит только исторические сущности.

`EntityAnnotation.entityId` — смысловой адресат. Необязательный `anchor` — место
наблюдения, которое может принадлежать другой сущности. Все шесть исходных ID,
описаний, вопросов и evidence references сохранены. Адресаты:

| Материал | Адресат |
|---|---|
| pistol-barrel | barrel |
| pistol-lock | lock |
| pistol-cock («Курок и огниво») | lock |
| pistol-stock | stock |
| pistol-ramrod | ramrod |
| pistol-grip («Рукоять и затыльник») | pistol |

Материалы о предках показываются отдельно как связанные материалы о целом.
Исторические атрибуции не расширены.

## Anchors

`SemanticEntity.focusAnchor.entityId` обязан совпадать с ID сущности. Привязки
рукояти, дульной области и клейма сохранены в данных. Воспроизводимый авторинг:
`node node_modules/tsx/dist/cli.mjs scripts/author-semantic-focus.ts`.
Скрипт получает точку и мировую нормаль raycast по существующей геометрии, включая
геометрию надписи, затем вызывает `anchorFromWorld(featureId, point, normal)`.
Новые meshes для region/feature не создаются. `createAnchor(hitObject, ...)`
предназначен для привязки к владельцу geometry binding и здесь не подменяет
авторинг feature. Точки следуют matrixWorld frame, нормали — inverse transpose.

## Позы и расчёт схемы

`AssemblyPose.offsets` — абсолютные суммарные поступательные смещения semantic
frames относительно baseline в координатах экспоната. Это не команды движения.
Дубли отклоняются до создания Map. Неперечисленный потомок наследует итоговое
смещение предка; явный offset ребёнка заменяет его. Локально применяется разность
итоговых смещений ребёнка и родителя с преобразованием в frame родителя.

`AssemblySystem` интерполирует позы за 550 мс, продолжает прерванный переход из
текущего состояния и поддерживает мгновенный reduced-motion. Он не рассчитывает
композицию и не имеет публичного amount. Сборка восстанавливает baseline.

`snapshotBounds` снимает локальные boxes каждого mesh и его baseline matrix один
раз до разборки. Чистый `AssemblyLayoutSolver` получает снимки, определения
сущностей, конфигурацию, reference view и размер рабочей области в CSS px.
Изменяемую сцену, WebGL, DPR и requestAnimationFrame solver не получает.
Для проекции используются восемь углов каждого локального box, а затем объединение
экранных прямоугольников внутри группы. Мировой AABB не используется как замена
этой проекции.

Направления заданы в плоскости опорной камеры: `[0,-1]` вверх, `[1,0]` вправо.
Последовательность ограничена: до 64 проходов расстановки → fit → проверка →
один корректирующий solve → при необходимости ряды desktop/колонка mobile →
финальный fit и проверка. Запасы расчёта больше приёмочного минимума; последняя
проверка требует 16 CSS px между группами и 24 CSS px от границ. Неудача возвращает
явную ошибку и не применяется к сцене. Предыдущая корректная поза сохраняется.

Layouts: overview (8 групп), lock (5 деталей), trigger (2 детали). Drill-down
скрывает остальной предмет. «Назад» возвращает родительскую схему и выбирает
закрытую группу; «Собрать всё» сбрасывает позу, выбор, режим и видимость.
«Вернуть схему» восстанавливает рассчитанный reference view. Перед восстановлением
сбрасывается остаточное damping-движение OrbitControls.

Solver вызывается при входе/смене layout и изменении workspace с debounce 150 мс.
Вращение, hover и обычный выбор расчёт не запускают. Workspace исключает панель,
шапку и нижние элементы интерфейса. Сравнение масштаба сначала завершает разборку;
смена экспоната сбрасывает runtime и состояние выбора.

Гарантия отсутствия пересечений действует в конечной позе и опорном ракурсе.
Она не распространяется на промежуточную анимацию и свободное вращение.

## Проверки и поставка

- `assembly-v2.test.ts`: occlusion, ghost policy, жесты, resolver, граф/конфигурация,
  абсолютные позы и прерывание, авторинг feature, аннотации, восемь углов,
  детерминизм, corrective solve, fallback и финальная проверка.
- `semantic-controls.test.tsx`: клавиатурное дерево, независимый фокус,
  синхронизация карточки, отсутствие virtual groups среди semantic nodes,
  ограничения действий для feature и английский интерфейс.
- `semantic-scene`, `semantic-presentation`, `camera-rig`: сохранение импортированных
  transforms, дрейф, материалы, anchors и управление камерой.
- `e2e/assembly.spec.ts`: 320/390/768/1280 CSS px, оба drill-down, возврат,
  isolate/ghost, смена экспоната, настоящая GLB и проверка всех layouts.
- `e2e/pistol.spec.ts`: прямой click, drag с возвратом, touch/pinch/cancel,
  обычная анимация и прерывание, локализация.
- `content-validation` и `viewer-lifecycle`: загрузка следующего экспоната,
  сон WebGL в покое, вращение и context loss.

Baseline исходного коммита `d024856` снят отдельно. Первый прогон с обычным
hook timeout пропустил девять тестов пистолета после сбоя beforeAll. Контрольный
прогон исходного коммита с `--hookTimeout=120000` выполнил все 78 тестов:
69 pass / 9 fail. Исторические ошибки — восемь ожиданий скрытого ancient-rus
и лимит 150000 треугольников при фактических 249480. Их исправление не входит
в эту поставку; геометрия и лимит не меняются.

Отчёты лежат в `artifacts/assembly-v2-*.json`, скриншоты —
`artifacts/assembly-v2-*.png` и `artifacts/assembly-overview-*.png`.
Сравнение baseline выполняется по suite/test name и первой строке причины,
а не по числу ошибок. Итоговые результаты фиксируются в отдельном отчёте проверки.

Два логических блока поставки: Direct Semantic Interaction и Hierarchical Assembly.
Физическая симуляция, третий уровень разборки, новые исторические атрибуции,
публикация сервиса и исправление старых падений не входят в эту версию.

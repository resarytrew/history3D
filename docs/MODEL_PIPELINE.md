# Подготовка 3D-моделей

[← Документация](README.md)

Runtime поддерживает procedural factories и GLB. Оба пути заканчиваются контрактом `LoadedExhibitModel { root, dispose }`; модель не владеет renderer или камерой.

## Procedural

Factory возвращает Three.js Group. Геометрия должна быть воспроизводимой, а geometry/material/texture — доступными штатному обходу освобождения ресурсов. Регистрация использует ленивый импорт по factoryId.

Все три активных экспоната сейчас загружаются процедурно. Пистолет дополнительно экспортируется в GLB, и существующий бинарный файл проверяется теми же семантическими контрактами в браузере.

## GLB

Предпочтителен самодостаточный glTF 2.0 GLB с проверенными материалами и стабильными именами узлов. Текущий загрузчик использует fetch, AbortSignal и GLTFLoader; необязательная normalization задаёт targetHeight, центрирование, установку на землю и rotation.

Не считайте объявленный descriptor доказательством поддержки сжатия: текущий загрузчик не подключает Draco/Meshopt-декодеры. Их внедрение требует отдельного изменения и проверки реального файла.

После экспорта проверьте bounds, имена meshes, материалы, текстуры и семантические bindings через импорт GLB. Sanitization имён загрузчиком может изменить связь с исходным именованием.

## Координаты и семантика

Базовая договорённость — метры и +Y вверх. Orientation, cameraPosition и cameraTarget согласуются с конкретным пакетом. Систему координат импортированной геометрии при необходимости приводит normalization.

Не меняйте parentId ради удобства экспорта или разборки. Scene graph отвечает за геометрию; SemanticEntity — за историческую структуру. SemanticSceneIndex сохраняет исходные transforms и создаёт собственные frames.

Focus anchors сериализуются в entity-local координатах. Для feature без binding точка может быть получена raycast по несущей детали, но сохраняется через `anchorFromWorld(featureId, ...)`.

## Геометрия и производительность

Измеряйте triangles, meshes/draw calls, объём GLB и текстур, время подготовки и поведение на мобильном устройстве. Общая цифра не заменяет проверку загрузки и взаимодействия.

Проверенный пистолет содержит **249480 треугольников**. Старый тест с лимитом 150000 остаётся известным падением; его нельзя представлять как пройденный бюджет или молча повышать порог. Оптимизация и согласование бюджета — отдельная задача.

В покое RenderScheduler не поддерживает постоянный цикл отрисовки. Это не устраняет стоимость первого procedural build и создания ресурсов.

## Экспорт и контрольные виды

| Команда | Результат |
| --- | --- |
| `npm run build:pistol` | Экспорт и контрольные материалы пистолета |
| `npm run verify:pistol` | Экспорт, аудит и галерея уточнений |
| `npm run verify:shako` | Фиксированные виды и метрики кивера |
| `npm run verify:musket` | Виды и метрики ружья |
| `npm run verify:3d` | Проверка сохранённой модели Покрова |

Скрипты могут обновлять GLB, изображения и отчёты. Просмотрите изменения до включения в коммит. Старый файл metrics не подтверждает текущую геометрию без совпадающей версии/хеша.

## Посетительская загрузка

До первого готового кадра показывается индикатор. Poster не заменяет сцену при загрузке или ошибке. Смена экспоната отменяет устаревшую загрузку; её поздний результат освобождается.

Assets текущих пакетов преимущественно PNG. AVIF/WebP, LOD, decoder-based compression и preload следующего предмета не следует описывать как уже включённые оптимизации.
